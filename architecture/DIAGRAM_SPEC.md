# Diagram Generation Specification

## 1. Целевые диаграммы (корень проекта)

### 1.1 Общие диаграммы
| Файл          | Назначение                              | Источник данных                          |
|---------------|-----------------------------------------|------------------------------------------|
| SYSTEMS.mmd   | Системный контекст (C4 Context)         | `KNOWLEDGE_MAP.md` (разделы Systems)     |
| MODULES.mmd   | Декомпозиция модулей и связи           | `CONTRACT_REGISTRY.md` (контракты)       |

### 1.2 Диаграммы потоков (по одному файлу на процесс)
| Шаблон файла   | Назначение                              | Источник данных                          |
|----------------|-----------------------------------------|------------------------------------------|
| `FLOW-<ID>.mmd` | Sequence-диаграмма одного процесса     | `KNOWLEDGE_MAP.md` (раздел Flows)        |

- **Правило**: каждая запись вида `## FLOW-<ID>: ...` в `KNOWLEDGE_MAP::Flows` порождает отдельный файл `FLOW-<ID>.mmd` в корне проекта.
- **Примеры**: `FLOW-01.mmd`, `FLOW-02.mmd`, `FLOW-03.mmd`.
- При добавлении в KNOWLEDGE_MAP нового потока (например, FLOW-05) создаётся новый файл `FLOW-05.mmd`. Удалённые потоки не удаляют старые файлы (index discipline: deprecated остаются), но генератор может не создавать файлы для потоков, отсутствующих в актуальном разделе Flows.

## 2. Правила трансформации

- **SYSTEMS.mmd** — Mermaid `flowchart TD`. Каждая запись в `KNOWLEDGE_MAP::Systems` → узел, связи — из раздела `Relations` (или из CONTRACT_REGISTRY по consumer/provider).
- **MODULES.mmd** — Mermaid `classDiagram`. Каждый контракт из `CONTRACT_REGISTRY` → класс/компонент. Зависимости — из consumer/provider.
- **FLOW-<ID>.mmd** — Mermaid `sequenceDiagram`. Один файл = один процесс. Источник — блок `## FLOW-<ID>: <name>` в `KNOWLEDGE_MAP::Flows`:
  - **Участники (participant)**: из поля «Участвующие системы» (в порядке появления в потоке).
  - **Сообщения (стрелки)**: из нумерованных «Шаги»; каждый шаг — вызов/ответ между системами.
  - При наличии `PROMPT_INDEX_MAP` для данного потока — lifelines/стрелки могут дополняться по `uses` / `next_prompt`.

## 3. Условия автообновления

- При изменении `KNOWLEDGE_MAP.md` (разделы Systems или Flows) — перегенерировать `SYSTEMS.mmd` и все `FLOW-<ID>.mmd`, соответствующие текущему списку потоков в Flows.
- При изменении `CONTRACT_REGISTRY.md` — перегенерировать `MODULES.mmd` (и при необходимости `SYSTEMS.mmd` для связей).
- При изменении `PROMPT_INDEX_MAP.md` — перегенерировать затронутые `FLOW-<ID>.mmd` (если спецификация связывает промпты с потоками).
